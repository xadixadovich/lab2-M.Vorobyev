## 3. Листинги модулей с комментариями

### 3.1. Модуль 1 — `chapter1.bat` (выбор технологии)

Интерактивная система поддержки принятия решений: пользователь отвечает на
5 вопросов о характеристиках проекта, каждый ответ начисляет баллы трём
кандидатам, в конце выводится таблица баллов и рекомендация.

Ключевые участки кода:

* `set score_youtrack=0` и далее — объявление счётчиков «профиля проекта»
  для каждого кандидата.
* `choice /c 123 /n /m "..."` — ввод ответа нажатием одной клавиши, без
  подтверждения клавишей Enter.
* `if errorlevel 3 goto q1c3` — ветвление: проверки идут от старшего кода к
  младшему, потому что `if errorlevel N` истинно при `errorlevel >= N`.
* `set /a score_taiga+=10` — накопление баллов в числовых переменных.
* `:calc` — поиск максимального балла и определение победителя тремя
  отдельными `if` (без блоков `( )`), чтобы избежать подстановки переменных
  на этапе разбора блока.
* `:tie` — обработка ничьей: если максимальный балл у двух и более
  кандидатов, выводится соответствующее сообщение.
* `set "RESULT_TECH=..."` — передача результата главному файлу.

### 3.2. Модуль 2 — `chapter2.bat` (инспекция кода)

Модуль формализации процесса ревьюирования: показывает 5 фрагментов кода
интеграции с трекером задач, в каждом спрятан один дефект. За правильный
ответ начисляется +1 балл, за неправильный — снимается 1 балл.

Ключевые участки кода:

* `set correct=0`, `set total=5`, `set score=0` — счётчики правильных
  ответов, общего числа фрагментов и итогового балла.
* `:f1` … `:f5` — экраны с фрагментами кода и четырьмя вариантами дефекта
  (неинициализированная переменная, мёртвое присваивание, утечка ресурса,
  магическое число, отсутствие обработки ошибок).
* `if errorlevel 4 goto f1c4` — разбор выбранного варианта; последняя ветка
  (вариант 1) реализована как переход по умолчанию.
* `set /a score-=1` / `set /a score+=1` — штраф за ошибку и балл за верный
  ответ; после каждого ответа печатается пояснение (чек-лист ревью).
* `set /a percentage=correct*100/total` — расчёт точности в целых числах с
  ограничением диапазона 0–100.
* `if %percentage% geq 80 ...` — определение уровня ревьюера
  (Senior / Middle / Junior).
* `set "RESULT_REVIEW=..."` — передача результата главному файлу.

### 3.3. Модуль 3 — `chapter3.bat` (сравнительный анализ, WSM)

Сравнительный анализ альтернатив методом взвешенной суммы
**S = Σ(Wᵢ · Xᵢ)**: пользователь сам назначает веса четырём критериям,
затем оценивает три альтернативы по шкале 1–5, модуль считает взвешенные
суммы, выводит матрицу решений и объявляет победителя.

Ключевые участки кода:

* `set /a total_weight=w1+w2+w3+w4` и `if %total_weight% neq 100 (...)` —
  проверка, что сумма весов равна 100, с повторным вводом через `goto start`.
* `:read_rating` — подпрограмма чтения оценки: отбрасывает буквы и числа вне
  диапазона 1–5, возвращая значение в переменной `%rv%`.
* `:pad30`, `:pad4`, `:pad9` — подпрограммы выравнивания текста и чисел,
  благодаря которым матрица решений остаётся ровной при любых значениях.
* `set /a s_y=y1*w1+y2*w2+y3*w3+y4*w4` — расчёт S для каждой альтернативы.
* `set /a fy=s_y%%100` — нормированная оценка `S/100` в шкале 0–5
  (целая и дробная части считаются отдельно, так как `set /a` работает
  только с целыми числами).
* `:w_single` / `:w_tie` — объявление победителя и обработка ничьей.

### 3.4. Главный модуль — `lab_system.bat` (интеграция)

Объединяет три модуля в единую систему: главное меню, вызов модулей
командой `call` и формирование итогового отчёта в файле `report.txt`.

Ключевые участки кода:

* `cd /d "%~dp0"` — работа относительно папки скрипта, а не текущего
  каталога (важно при запуске из ярлыка или другого места).
* `set "RESULT_..." = пусто` в начале — очистка результатов предыдущих
  запусков, чтобы отчёт не содержал устаревших данных.
* Пункты меню `1`–`3` вызывают отдельный модуль, пункт `4` — все три
  последовательно (`call chapter1.bat`, `call chapter2.bat`,
  `call chapter3.bat`).
* `call` (а не простой запуск) используется потому, что при `call` модуль
  выполняется в том же процессе `cmd`, и переменные `RESULT_*` остаются
  доступны главному файлу.
* `:report` — сборка итогового отчёта; для не запускавшихся модулей
  подставляется заглушка «не запускался».
* `> report.txt echo ...` и `>> report.txt echo ...` — запись отчёта
  в файл (первая строка перезаписывает, остальные дописываются).

## 7. Описание того, что получилось при запуске интегрированной системы

### 7.1. Какие диалоги и вопросы задавались в каждом модуле

**Модуль 1 — выбор технологии.** Пять вопросов, ответ — нажатие клавиши `1`–`3`:

1. Сколько человек будет работать в трекере (до 5 / 6–15 / больше 15).
2. Какой бюджет выделен на систему трекинга (только бесплатное / до
   500 ₽ в месяц за пользователя / бюджет есть, важнее удобство).
3. Как быстро нужно запустить трекер и есть ли администратор
   (запуск за день без админа / неделя и один администратор / свой сервер).
4. Насколько важна гибкая настройка рабочих процессов
   (готовый Scrum из коробки / готовы настраивать workflow /
   нужна глубокая кастомизация и открытый код).
5. Насколько важны готовые интеграции с Git и CI
   (критичны / достаточно REST API / не важны).

После ответов модуль печатает таблицу баллов и рекомендацию с обоснованием.

**Модуль 2 — инспекция кода.** Пять фрагментов кода на Python с вопросом
«Какой дефект здесь скрыт?» и четырьмя вариантами ответа: мёртвое
присваивание, неинициализированная переменная, магическое число, утечка
ресурса, отсутствие обработки ошибок. После каждого ответа выводится
пояснение, в конце — количество правильных ответов, точность и уровень
ревьюера.

**Модуль 3 — сравнительный анализ.** Сначала четыре вопроса о весах
критериев (гибкость Scrum, стоимость владения, интеграции, простота
освоения) с проверкой, что сумма равна 100, затем 12 оценок
«альтернатива × критерий» по шкале 1–5. Модуль выводит матрицу решений и
победителя.

## 8. Инструкция по запуску системы для другого пользователя

**Требования:** Windows 10 или Windows 11, интерпретатор `cmd.exe`
(входит в систему). Дополнительные программы, библиотеки и права
администратора не нужны.

1. Скачать репозиторий: `git clone <ссылка на репозиторий>` или нажать на
   странице репозитория **Code → Download ZIP** и распаковать архив.
2. Убедиться, что все четыре `.bat`-файла лежат в одной папке
   (`chapter1.bat`, `chapter2.bat`, `chapter3.bat`, `lab_system.bat`).
3. Запустить нужный модуль двойным кликом:
   * `chapter1.bat` — модуль выбора технологии;
   * `chapter2.bat` — модуль инспекции кода;
   * `chapter3.bat` — модуль сравнительного анализа;
   * `lab_system.bat` — вся система целиком (рекомендуемый способ).
4. В главном меню ввести `4` — система последовательно запустит все три
   модуля и покажет итоговый отчёт. Для выхода из меню — пункт `5`.
5. Файл `report.txt` появится в той же папке, где лежат скрипты.
6. Ответы вводятся нажатием клавиши (`choice`) или набором числа и Enter
   (`set /p`); после завершения модуля нажмите любую клавишу, чтобы
   вернуться в меню.
   
Если вместо русского текста видны непонятные символы — значит файл открылся
в другой кодировке. Все .bat сохранены в UTF-8 без BOM, а в начале стоит
chcp 65001, поэтому в обычной командной строке Windows 10/11 всё показывается
нормально.
